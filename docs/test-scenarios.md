# Тестовые сценарии

Пошаговая проверка решения: тестовые учётные записи, демо-сценарии клиента и андеррайтера, коллекция Postman и автотесты. Каждый шаг можно пройти в веб-интерфейсе или запросами к API: в скобках указан вызов API (базовый адрес `http://localhost:8080/api/v1`, полное описание — Swagger UI `http://localhost:8080/api/v1/swagger-ui.html`). Как считаются баллы, лимиты и условия — [`scoring.md`](scoring.md).

Перед началом запустите весь стенд командой `docker compose up -d --build --wait` из корня репозитория. В `docker compose ps` все четыре сервиса должны быть `healthy`; кабинет доступен по адресу http://127.0.0.1:5173. Параметры запуска и сохранение базы описаны в [корневом README](../README.md).

Автоматический прогон этих сценариев через Nginx: `cd frontend`, затем `npm run test:e2e:docker`. Он использует работающий Docker-стенд, реальные API и PostgreSQL, проверяет интерфейс на desktop и mobile. Подготовка браузера и артефакты проверки описаны в [README](../README.md#проверка-docker-стенда-в-браузере).

## Общий порядок для клиента

1. Войти клиентом, выбрать компанию.
2. Подобрать продукт (`POST /products/match`) или выбрать из каталога (`GET /products`), нажать «Оформить» или «Оформить с подпиской» — создаётся черновик (`POST /applications`).
3. Заполнить анкету (`PATCH /applications/{id}`): суммы — в рублях, выручка и расходы — за год, платежи по кредитам — в месяц.
4. Отправить (`POST /applications/{id}/submit`) — сразу статус `SUBMITTED`, решение через 1–2 секунды (`GET /applications/{id}`, уведомление в кабинете).
5. По решению: принять или отклонить предложение (`offer/accept`, `offer/decline`), ответить на запрос сведений, подписать кодом (`signing/request-code` — в демо код показан на экране, `signing/confirm`).
6. История заявки — все переходы с автором и временем (`GET /applications/{id}/history`).

Какие действия доступны в текущем статусе — поле `availableActions` заявки, подсказка клиенту — `nextStepHint`.

## Сценарии андеррайтера

Войти сотрудником банка — в другом окне браузера (или выйти из кабинета клиента). Очереди: «На проверке» (`GET /backoffice/applications?queue=REVIEW`), «На подтверждении» (`queue=CONFIRMATION`), все заявки (`queue=ALL`); дольше ждущие — первыми. Карточка заявки (`GET /backoffice/applications/{id}`) — анкета, компания, ответы ЕГРЮЛ/ФНС/БКИ, балл с разбивкой по факторам, причины, история, запросы сведений, документы.

### 10. Ручная проверка → одобрение сотрудником — ИП Морозов

| Шаг | Кто | Действие | Ожидаемый результат |
|---|---|---|---|
| 1 | клиент | Сценарий 4 | `MANUAL_REVIEW` |
| 2 | андеррайтер | Открыть заявку из очереди «На проверке» | карточка: балл 75 (B), просрочка 45 дней, причина `OVERDUE_31_60` |
| 3 | андеррайтер | Одобрить без изменения условий (`POST …/decision` с `{"decision": "APPROVE"}`) | `APPROVED`, предложение не предварительное: «Одобрен лимит 1 000 000 ₽, транши до 6 месяцев»; в истории — имя сотрудника |
| 4 | клиент | Принять → запросить код → ввести код | `OFFER_ACCEPTED` → `SIGNED` → `DISBURSED` |

| Шаг | Кто | Действие | Ожидаемый результат |
|---|---|---|---|

### Что ещё можно проверить

| Проверка | Ожидаемый результат |
|---|---|
| Клиент открывает бэк-офис, андеррайтер — заявки клиента | `403` |
| Запрос без токена (кроме входа, `health` и Swagger UI) | `401` |
| Недопустимое действие в текущем статусе (например, принять предложение у черновика) | `409` «Действие недоступно» |
| Предложение без ответа 7 дней | `OFFER_EXPIRED`, принять нельзя (`409`) — проверяется автотестами с подменой времени |

## Коллекция Postman

`docs/api/credit-conveyor.postman_collection.json` — 13 сценариев с автопроверками: 9 клиентских (сценарии 1–9 выше) и 4 андеррайтера (10–13). Сценарий с недоступным источником и загрузка документов в коллекцию не входят.

1. Запустить стенд.
2. В Postman: **Import** → файл коллекции.
3. Если бэкенд не на порту 8080 — поменять переменную коллекции `baseUrl` (по умолчанию `http://localhost:8080/api/v1`).
4. Запуск: правый клик по коллекции → **Run collection** → **Run**. Сценарии сами входят нужной ролью, создают заявки и ждут асинхронного решения; все проверки должны быть зелёными.

Из командной строки (нужен Node.js):

```bash
npx newman run docs/api/credit-conveyor.postman_collection.json
```

С другим портом — `--env-var baseUrl=http://localhost:<порт>/api/v1`. Коллекцию можно запускать повторно: каждый прогон создаёт новые заявки.

## Автотесты

Из папки `backend` (нужны Java 21 и запущенный Docker — интеграционные тесты поднимают PostgreSQL через Testcontainers и WireMock с моками из `mocks/wiremock`):

```bash
./mvnw clean verify
```

| Что проверяют | Тесты |
|---|---|
| Скоринг и кредитная политика: факторы, полосы, грейды, порядок проверок, лимиты, условия предложения | `ScorerTest`, `CreditPolicyTest`, `OfferCalculatorTest` |
| Машина состояний: все 32 разрешённых перехода, любые другие комбинации «из — в — кто» → `409`, кнопки и подсказки | `StatusTransitionsTest` |
| Сквозной конвейер по всем демо-компаниям, недоступные и медленные источники, повторная доставка событий | `ConveyorIntegrationTests`, `EventRedeliveryIntegrationTests` |
| Жизненный цикл заявки, PATCH, истечение предложений, подписание | `ApplicationLifecycleIntegrationTests` |
| Бэк-офис, уведомления и поток SSE, документы | `BackofficeIntegrationTests`, `NotificationIntegrationTests`, `DocumentsIntegrationTests` |
| Безопасность: токены, роли, доступ только к своим компаниям | `SecurityIntegrationTests`, `ControllerSecurityTest`, `CompaniesIntegrationTests` |
| Совпадение с примерами контракта, ошибки `400` | `ApiIntegrationTests`, `ApiExceptionHandlerTest`, `ReasonCodesTest` |
| Границы модулей | `ModularityTests` |
