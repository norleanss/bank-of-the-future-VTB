# Умный кредитный кабинет — frontend

React, TypeScript и Vite, собственный UI-кит на CSS Modules. Требуется Node.js 22.12+.

Для запуска готового кабинета вместе с backend, PostgreSQL и WireMock используйте
`docker compose up -d --build --wait` из корня репозитория — подробности в
[общем README](../README.md). Node.js на компьютере нужен для разработки и тестов;
Docker-стенд собирает фронтенд в Node 22 и отдаёт статические файлы через Nginx.

```sh
npm ci
npm run dev
```

## Подключение API

По умолчанию включён локальный mock. Для HTTP скопируйте `.env.example`
в `.env.local` и задайте:

```dotenv
VITE_API_MODE=http
VITE_API_BASE_URL=/api/v1
API_PROXY_TARGET=http://localhost:8080
```

Перезапустите Vite. Запросы `/api/v1` идут через dev proxy на backend;
для локальной разработки CORS не требуется. `API_PROXY_TARGET` — адрес сервера
без `/api/v1`, он не попадает в клиентский код. Для возврата к демо
задайте `VITE_API_MODE=mock` и перезапустите Vite.

Адаптер использует [контракт API 0.2.3](../docs/api/openapi.yaml), полученный
из `origin/master` (fb01b99); backend из `origin/backend` (2f3d2c9) включён в репозиторий.
Суммы передаются десятичными строками, срок — парой `term` / `termUnit`.
Изменение заявки — JSON Merge Patch с `Content-Type: application/json`, как в контракте backend.
Статусы обновляются опросом каждые 2,5–3 секунды. Уведомления приходят по SSE;
после переподключения список перечитывается, резервный опрос — каждые 10 секунд.

В HTTP-режиме доступны подбор с предварительным платежом и комиссией,
асинхронное решение, запросы сведений и документы, принятие предложения,
подписание, выдача и бэк-офис. Окончательные платежи и советы берутся из ответа
банка. Ответы `501` показываются как недоступное действие.

В карточке заявки есть история и скачивание документов с авторизацией.
У сотрудника документы и все запросы сведений берутся из карточки бэк-офиса;
клиентские эндпоинты для этой роли не вызываются. Подтверждение предварительного
предложения отправляется без новых условий. Другой продукт или другие условия
задаются через контрпредложение. В ответ на запрос сведений прикладываются только
документы, ещё не связанные с предыдущими ответами. Лимиты загрузки: PDF/JPG/PNG,
до 10 МБ на файл и до 20 файлов на заявку; содержимое проверяет backend.

Уведомления всех компаний доступны по ссылке в шапке; можно перейти к заявке,
отметить уведомление прочитанным или посмотреть только непрочитанные.

## Демо

Вход по роли, без телефона. Клиент выбирает одну из шести компаний:
одобрение, ручная проверка, отказ по просрочке, предварительное одобрение,
Гамма-Старт или отказ по ликвидации. Для ручной проверки и подтверждения
условий войдите сотрудником банка и откройте соответствующую очередь.

Пример заявки: оборудование, 2 000 000 ₽, 24 месяца, вся сумма сразу.
Финансы: выручка 12 000 000 ₽, расходы 8 000 000 ₽,
оборот по счёту 1 000 000 ₽/мес., платежи по кредитам 0.
Для Гамма-Старта финансовые поля необязательны.

Mock обрабатывает заявку примерно за 6 секунд и использует заранее заданные
сценарии. Подписание подтверждается кодом внутри кабинета. Дополнительные
состояния доступны в блоке «Демонстрация состояний» только в mock-режиме.
Подбор проверяет сумму, срок, способ выдачи и возраст бизнеса. Цель задаёт
порядок рекомендаций, а бизнесу младше 12 месяцев первым предлагается
подходящий Гамма-Старт.

Заявки и черновики сохраняются в localStorage отдельно для компаний и режимов
API. Выход не удаляет их. Ключи начинаются с `gamma-credit:` и
`gamma-credit-cabinet:mock:v1`.
В mock содержимое загруженных файлов тоже сохраняется в localStorage; доступный
объём ограничен квотой браузера. В HTTP-режиме документы хранятся на backend.

## Проверки

```sh
npm run lint
npm run typecheck
npm test
npm run build
npx playwright install chromium
npm run test:e2e
npm run test:e2e:http
npm run test:e2e:live
npm run test:e2e:docker
```

Для установленного Edge в PowerShell: `$env:PLAYWRIGHT_CHANNEL='msedge'`.
HTTP-набор поднимает отдельный Vite на порту 5174 в HTTP-режиме и перехватывает
API-запросы в браузере: проверяет авторизацию, JSON Merge Patch, привязку документов,
скачивание для обеих ролей, подтверждение условий и уведомления. Это проверки
интеграции фронтенда с контрактом, они не запускают Spring Boot/PostgreSQL.
Обычный E2E-набор использует mock на порту 5173; результаты наборов хранятся отдельно.

`test:e2e:live` требует работающий backend (`http://localhost:8080`), PostgreSQL
и WireMock из ветки `backend`. Он запускает отдельный фронтенд на 5175, не
перехватывает API-запросы и создаёт реальные заявки в демобазе. Проверяются
оформление через анкету, скоринг, подписание и выдача, уведомления SSE, запросы
сведений, загрузка и скачивание документов обеими ролями, ручное решение,
подтверждение крупной суммы, отказ и Гамма-Старт. Есть desktop и mobile проекты;
результаты — `test-results-live`. Другой адрес API задаётся через `API_PROXY_TARGET`.

`test:e2e:docker` использует те же реальные сценарии и проверку Nginx, но обращается
к уже запущенному Docker-стенду на `http://127.0.0.1:5173`. Он не запускает Vite.
Для другого адреса задайте `DOCKER_BASE_URL`; результаты — `test-results-docker`.
Проверяются прямые ссылки SPA, собранные ресурсы, SSE без буферизации и загрузка
файла больше 1 МиБ с побайтовой проверкой скачивания клиентом и сотрудником.

## Код

- `src/app` — маршруты, layout, настройки запросов.
- `src/pages`, `src/features` — экраны и пользовательские сценарии.
- `src/entities` — отображение заявок и валидация.
- `src/shared/api`, `src/shared/mocks` — HTTP-адаптер и mock.
- `src/shared/lib`, `src/shared/types`, `src/shared/ui` — хранение данных,
  форматирование, типы и общие состояния интерфейса.

При размещении SPA сервер должен отдавать `index.html` для клиентских маршрутов
и проксировать `/api/v1` на backend. Dev proxy не включается в сборку. Если API
размещён на другом домене, задайте абсолютный `VITE_API_BASE_URL` при сборке
и разрешите CORS на backend.
