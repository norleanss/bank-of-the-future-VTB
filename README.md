# Умный кредитный кабинет

Кабинет клиента и бэк-офис банка: подбор кредита, анкета, асинхронный скоринг,
запросы сведений и документов, предложение банка, подписание и выдача.
Все компании, условия и решения демонстрационные. ЕГРЮЛ, ФНС и БКИ имитирует WireMock.

## Запуск всего стенда в Docker

Нужны Git и запущенный Docker Desktop с Linux-контейнерами и Docker Compose v2+.
Локальные Java, Maven и Node.js для запуска стенда не требуются.
Из корня этого репозитория:

```sh
docker compose up -d --build --wait
docker compose ps
```

Первый запуск скачивает образы, Maven- и npm-зависимости. Следующие сборки используют
кэш. Готовый стенд — четыре сервиса со статусом `healthy`.

| Сервис | Адрес на компьютере | Назначение |
|---|---|---|
| Кабинет | http://127.0.0.1:5173 | Production-сборка React, которую отдаёт Nginx |
| API через Nginx | http://127.0.0.1:5173/api/v1/actuator/health/readiness | Проверка всего пути до backend; ответ `{"status":"UP"}` |
| API напрямую | http://localhost:8080/api/v1 | Spring Boot в отдельном контейнере |
| Swagger UI | http://localhost:8080/api/v1/swagger-ui.html | Контракт и запросы к API |
| WireMock | http://localhost:8089/__admin/health | Заглушки внешних источников |
| PostgreSQL | `localhost:55432` | База `credit_conveyor`, пользователь и пароль `credit` |

Браузер обращается к `/api/v1` на том же адресе, что и кабинет. Nginx передаёт запросы
на `backend:8080`, backend обращается к `postgres:5432` и `wiremock:8080` по сети Compose.
Vite в контейнерном стенде не запускается.
SSE передаётся без буферизации; query-параметры с токеном не записываются в access log Nginx.
После пересоздания backend прокси заново разрешает его имя в сети Docker.

Фронтенд собирается в Node.js 22, в конечном образе остаются Nginx и статические
файлы. Бэкенд собирается Maven 3.9.11 / Java 21, конечный образ содержит JRE 21.
Образы собираются из исходников в этой рабочей копии; соседние worktree не нужны.
Локальные `.env`, `node_modules`, `target`, `dist` и результаты тестов исключены из
контекста сборки.

## Параметры запуска

По умолчанию все параметры уже заданы в Compose. При необходимости скопируйте
корневой `.env.example` в `.env` и измените нужные значения. В PowerShell:

```powershell
Copy-Item .env.example .env
```

| Переменная | По умолчанию | Что меняет |
|---|---|---|
| `FRONTEND_PORT` | `5173` | Порт кабинета на компьютере |
| `BACKEND_PORT` | `8080` | Порт прямого доступа к API |
| `POSTGRES_PORT` | `55432` | Порт базы на компьютере; внутри сети остаётся `5432` |
| `WIREMOCK_PORT` | `8089` | Порт внешних заглушек на компьютере |
| `POSTGRES_DB` / `POSTGRES_USER` / `POSTGRES_PASSWORD` | `credit_conveyor` / `credit` / `credit` | Начальные параметры базы |
| `JWT_SECRET` | пусто | При пустом значении ключ случайный при каждом старте backend; заданный ключ — не короче 32 байт |
| `CORS_ALLOWED_ORIGINS` | адреса локальной разработки из `.env.example` | Прямые запросы к backend с другого origin |
| `COMPOSE_PROJECT_NAME` | `credit-conveyor` | Имя проекта и префикс его контейнеров и тома |

Все опубликованные порты привязаны к `127.0.0.1`. Если порт занят, измените его в
`.env` и снова выполните команду запуска. Внутренние адреса сервисов от этого не
меняются. Настройки из `frontend/.env.local` относятся к локальной разработке и не
попадают в Docker-образ. В Docker режим API фиксирован в `http`, базовый путь —
`/api/v1`; `API_PROXY_TARGET` используется только dev-сервером Vite.

## Первый сценарий

1. Откройте кабинет и нажмите «Войти как клиент». Пароля нет: это демо-вход по роли.
2. Выберите ООО «Северный ветер», кредит одной суммой: 500 000 ₽, 24 месяца.
3. Укажите выручку 20 000 000 ₽, расходы 14 000 000 ₽, платежи по кредитам 50 000 ₽.
   Оборот по счёту для этого продукта необязателен.
4. Отправьте заявку, дождитесь одобрения, примите предложение, запросите и введите
   показанный в кабинете демо-код. Результат — «Деньги выданы».
5. Для ручной проверки используйте ИП Морозова и вход сотрудника банка. Для крупной
   суммы с подтверждением сотрудником — ООО «ТехноПром».

Точные анкеты, учётные записи и ожидаемые результаты всех сценариев — в
[тестовых сценариях](docs/test-scenarios.md). Правила решения — в
[описании скоринга](docs/scoring.md).

## Проверка Docker-стенда в браузере

Стенд сначала должен быть запущен командой выше. Для запуска проверок на компьютере
нужны Node.js 22.12+ и браузер Playwright:

```sh
cd frontend
npm ci
npx playwright install chromium
npm run test:e2e:docker
```

Для установленного Edge в PowerShell перед запуском тестов задайте:

```powershell
$env:PLAYWRIGHT_CHANNEL = 'msedge'
```

Набор запускается против уже работающего Nginx: не поднимает Vite и не перехватывает
API. Он проверяет desktop и mobile: оформление до выдачи, уведомления, подтверждение
крупной суммы, автоматический и ручной запрос сведений, документы и контрпредложение,
отказ, Гамма-Старт. Для загрузки используется файл больше 1 МиБ, при скачивании
обеими ролями проверяется совпадение байтов. Дополнительно проверяются собранные JS,
кэширование, прямые ссылки SPA, проксирование API и получение SSE-события через Nginx.
Тесты создают заявки в демобазе и оставляют их для просмотра.
Всего запускаются 14 проверок: семь сценариев на каждом из двух профилей браузера.

Если порт кабинета изменён:

```powershell
$env:DOCKER_BASE_URL = 'http://127.0.0.1:8088'
npm run test:e2e:docker
```

Скриншоты и трассировки ошибок находятся в `frontend/test-results-docker`.
Остальные проверки и запуск фронтенда без Docker описаны в
[frontend/README.md](frontend/README.md); тесты backend — в
[backend/README.md](backend/README.md).

## Пересборка, логи и остановка

Все команды этого раздела выполняются из корня:

```sh
docker compose up -d --build --wait
docker compose logs --tail=100 backend frontend
docker compose logs -f backend frontend
docker compose restart backend
docker compose down
```

`down` сохраняет заявки, документы и уведомления в именованном томе `postgres-data`.
Перезапуск backend при пустом `JWT_SECRET` требует повторного входа. Имя проекта
определяет используемый том: сохраняйте одно и то же имя для повторного запуска.

Чтобы намеренно удалить демобазу и начать с исходных компаний:

```sh
docker compose down -v
docker compose up -d --build --wait
```

Команда `down -v` удаляет все заявки и документы этого Compose-проекта.

Если сервис не стал `healthy`, посмотрите `docker compose ps` и его логи.
Порядок запуска: PostgreSQL и WireMock → готовый backend → Nginx.
Healthcheck frontend проверяет Nginx; доступность API отдельно показывает
`/api/v1/actuator/health/readiness`. Встроенная документация API:
[OpenAPI 0.2.3-draft](docs/api/openapi.yaml), [памятка фронтенду](docs/api/README.md),
[Postman](docs/api/credit-conveyor.postman_collection.json),
[диаграммы](docs/diagrams.md).
