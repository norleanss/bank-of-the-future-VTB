# Тестовые сценарии

Пошаговая проверка решения: тестовые учётные записи, демо-сценарии клиента и андеррайтера, коллекция Postman и автотесты. Каждый шаг можно пройти в веб-интерфейсе или запросами к API: в скобках указан вызов API (базовый адрес `http://localhost:8080/api/v1`, полное описание — Swagger UI `http://localhost:8080/api/v1/swagger-ui.html`). Как считаются баллы, лимиты и условия — [`scoring.md`](scoring.md).

Перед началом запустите весь стенд командой `docker compose up -d --build --wait` из корня репозитория. В `docker compose ps` все четыре сервиса должны быть `healthy`; кабинет доступен по адресу http://127.0.0.1:5173. Параметры запуска и сохранение базы описаны в [корневом README](../README.md).

Автоматический прогон этих сценариев через Nginx: `cd frontend`, затем `npm run test:e2e:docker`. Он использует работающий Docker-стенд, реальные API и PostgreSQL, проверяет интерфейс на desktop и mobile. Подготовка браузера и артефакты проверки описаны в [README](../README.md#проверка-docker-стенда-в-браузере).

## Общий порядок для клиента

1. «Войти как клиент», выбрать компанию в переключателе «Демо-режим: выберите компанию».
2. «Подобрать кредит» — ответить на вопросы подбора (цель, сумма, срок) и «Показать подходящие продукты» (`POST /products/match`) или открыть «Все продукты каталога» (`GET /products`); на карточке продукта — «Оформить» или «Оформить с подпиской», создаётся черновик (`POST /applications`).
3. Заполнить анкету (`PATCH /applications/{id}`), на шаге «Финансовые данные» — «Выручка за 12 месяцев, ₽», «Расходы за 12 месяцев, ₽», «Платежи по текущим кредитам в месяц, ₽», для овердрафта — «Оборот по счёту в Гамма-Банке в месяц, ₽»; суммы в рублях. Кнопки — «Далее», на последнем шаге «Отправить заявку».
4. После отправки (`POST /applications/{id}/submit`) статус «Заявка отправлена» (`SUBMITTED`), затем «Проверяем данные компании», «Анализируем заявку» и решение — обычно через 1–2 секунды (`GET /applications/{id}`, уведомление в кабинете).
5. По решению: «Принять предложение» или «Отказаться от предложения» (`offer/accept`, `offer/decline`); на запрос банка — дополнить анкету или приложить документ и «Отправить данные» (`info-requests/{requestId}/response`); подписание — «Получить код для подписания» (в демо код показан на экране, `signing/request-code`), ввести код и «Подписать договор» (`signing/confirm`).
6. «История заявки» — все переходы с автором и временем (`GET /applications/{id}/history`).

Какие кнопки доступны в текущем статусе — поле `availableActions` заявки, подсказка клиенту — `nextStepHint`. Статусы в кабинете показаны по-русски (например, `APPROVED` — «Кредит одобрен», `DISBURSED` — «Деньги выданы»); в таблицах ниже — коды статусов из API.

**Балл и грейд клиент не видит.** Где в ожидаемом результате указан балл — его видно сотруднику банка в карточке заявки (вход «Войти как сотрудник банка», вкладка «Все заявки») или в ответе API бэк-офиса (`GET /backoffice/applications/{id}`, поле `scoring`).

### 14. Овердрафт без подписки и с подпиской — «Северный ветер»

|---|---|---|

## Сценарии андеррайтера

«Войти как сотрудник банка» — в другом окне браузера (или «Выйти» из кабинета клиента). Вкладки бэк-офиса: «На рассмотрении» (`GET /backoffice/applications?queue=REVIEW`), «Подтверждение условий» (`queue=CONFIRMATION`), «Все заявки» (`queue=ALL`); дольше ждущие — первыми. Решение: выбрать «Одобрить», «Предложить другие условия» или «Отказать» и «Сохранить решение» (`POST …/decision`); запрос клиенту — «Запросить сведения» (`POST …/info-requests`). Карточка заявки (`GET /backoffice/applications/{id}`) — анкета, компания, ответы ЕГРЮЛ/ФНС/БКИ, балл с разбивкой по факторам, причины, история, запросы сведений, документы.

## Коллекция Postman

`docs/api/credit-conveyor.postman_collection.json` — 14 сценариев с автопроверками: клиентские 1–9 и 14 (овердрафт) и 4 сценария андеррайтера (10–13). Сценарий с недоступным источником и загрузка документов в коллекцию не входят.

1. Запустить стенд.
2. В Postman: **Import** → файл коллекции.
3. Если бэкенд не на порту 8080 — поменять переменную коллекции `baseUrl` (по умолчанию `http://localhost:8080/api/v1`).
4. Запуск: правый клик по коллекции → **Run collection** → **Run**. Сценарии сами входят нужной ролью, создают заявки и ждут асинхронного решения; все проверки должны быть зелёными.

Из командной строки (нужен Node.js):

```bash
npx newman run docs/api/credit-conveyor.postman_collection.json
```

С другим портом — `--env-var baseUrl=http://localhost:<порт>/api/v1`. Коллекцию можно запускать повторно: каждый прогон создаёт новые заявки.
